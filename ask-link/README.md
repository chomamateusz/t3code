# Ask-only links: what each file shows

Two T3 Code servers run side by side: "Workstation" holds a thread with some project facts, and "Build box" has an agent that needs one of those facts. Build box is linked to Workstation at the new access level "Ask only".

- `01-workstation-thread-menu.png`: On Workstation, the thread menu of "Release plan" has the new "Answer linked questions" item. It is off by default, and only threads where you switch it on can be asked anything.
- `02-workstation-answers-chip.png`: Once the opt-in is on, the thread header shows "Answers linked questions", so you can see which threads other machines may ask.
- `03-workstation-links-into-this-machine-ask.png`: Settings → Environments → List on Workstation, with "Links into this machine" set to "Ask only". This caps what any machine linking in may do: here it may ask, and nothing more.
- `04-buildbox-link-dialog-ask-only.png`: On Build box, the link dialog with "Ask only" picked. An Ask only link takes only a link code made with `t3 auth pairing create --link ask` on the other machine. The dialog says so, and warns that a general pairing code is refused and used up.
- `05-buildbox-linked-ask-only.png`: After linking, Build box lists Workstation as "Ask only · Reachable".
- `06-buildbox-agent-asks-over-link.png`: A real agent turn on Build box (Claude Haiku 5.5). The agent finds the opted-in thread with t3_ask_list ("List threads that answer linked questions"), asks it with t3_ask_send ("Ask a thread on a linked machine"), and reads the reply with t3_ask_wait ("Wait for a linked question's answer"). The answer, v2.4 on Friday, March 12, 2027, codename Bluefin, comes from the Release plan conversation on Workstation. The "echo placeholder" row is a stray no-op command the model ran on its own machine, unrelated to the link.
- `07-workstation-question-thread-answered.png`: On Workstation, the question shows up as a separate thread titled with the question and marked "From T3 Code · Build box", and it has already been answered. Question threads take no follow-up messages: the send button explains that the thread answered a question from Build box and takes no messages.
- `08-buildbox-other-tools-refused.png`: Back on Build box, the agent tries other tools over the same link (t3_thread_read on the Release plan thread, and t3_project_list). Both are refused with capability_denied: "Linked environment "Workstation" was linked for questions only."
- `09-workstation-release-plan-unchanged.png`: The asked thread "Release plan" afterwards. The question never entered it and it got no new message: the question and its answer live only in their own thread, listed above it in the sidebar.
- `ask-demo.mp4` / `ask-demo.gif`: The whole round trip in about 40 seconds, with a caption bar naming the machine on screen. The agent on Build box gets the task and calls the ask tools. The question arrives on Workstation as its own thread and is answered there. The answer comes back to the agent on Build box. Waiting time is sped up in the first two parts.
